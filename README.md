# بوابة آروب سورية للإبلاغ عن حوادث الأسطول

بوابة عربية لتقديم بلاغات حوادث المركبات، حفظ البلاغ مؤقتاً عند انقطاع الاتصال بعد فتح التطبيق، وإدارة البلاغات من لوحة محمية للمستخدمين الإداريين.

## المتطلبات

- Node.js 22 أو إصدار متوافق مع Next.js 16 (الحد الأدنى المدعوم 20.9).
- pnpm 12.3.4، وفق `packageManager` في `package.json`.
- PostgreSQL يمكن للتطبيق الوصول إليه.
- مساحة تخزين دائمة للوسائط المرفوعة إذا كانت البلاغات ستُحفظ على خادم بعيد.

## الإعداد المحلي

1. ثبّت الاعتماديات:

   ```sh
   pnpm install --frozen-lockfile
   ```

2. انسخ `.env.example` إلى `.env` واضبط القيم المحلية. لا ترفع `.env` أو تشارك محتواه.
3. أنشئ عميل Prisma وشغّل ترحيلات قاعدة البيانات:

   ```sh
   pnpm exec prisma generate
   pnpm db:migrate:deploy
   ```

4. في التهيئة الأولية فقط، عيّن بيانات المدير ثم أنشئه:

   ```sh
   pnpm exec prisma db seed
   ```

   كلمة المرور الأولية يجب أن تكون فريدة، لا تقل عن 12 محرفاً، وستُفرض إعادة تعيينها عند أول دخول. لا تشغّل seed كجزء من كل نشر؛ فهو يحدّث بيانات اعتماد المدير من متغيرات البيئة.

5. ابدأ خادم التطوير:

   ```sh
   pnpm dev
   ```

## متغيرات البيئة

| المتغير | مطلوب | الغرض |
| --- | --- | --- |
| `DATABASE_URL` | نعم | عنوان اتصال PostgreSQL بصيغة `postgresql://` أو `postgres://`. |
| `JWT_SECRET` | نعم | سر عشوائي لا يقل عن 32 بايت لتوقيع جلسات لوحة الإدارة. لا تستخدم قيمة المثال أو قيمة مشتركة بين البيئات. |
| `ADMIN_EMAIL` | للتهيئة الأولية | البريد الذي ينشئه seed لحساب المدير. |
| `ADMIN_PASSWORD` | للتهيئة الأولية | كلمة مرور أولية فريدة بطول 12 محرفاً على الأقل؛ غيّرها بعد الدخول الأول. ليست كلمة مرور افتراضية آمنة. |
| `ADMIN_NAME` | لا | اسم المدير الأول؛ القيمة الافتراضية «مدير النظام». |
| `NEXT_PUBLIC_EMERGENCY_PHONE` | لا | رقم الطوارئ الظاهر للمستخدمين؛ القيمة الافتراضية `963966888943`. هذا المتغير عام ويُضمّن في الواجهة. |
| `INCIDENT_SUPERVISOR_1_NAME`, `INCIDENT_SUPERVISOR_1_PHONE` | لا | اسم ورقم المشرف الأول لرسائل التواصل الاختيارية. |
| `INCIDENT_SUPERVISOR_2_NAME`, `INCIDENT_SUPERVISOR_2_PHONE` | لا | اسم ورقم المشرف الثاني لرسائل التواصل الاختيارية. |
| `APP_HEALTH_URL` | للمراقبة الخارجية | رابط `GET /api/health` الذي يفحصه سكربت المراقبة. |
| `HEALTH_ALERT_TO`, `HEALTH_ALERT_FROM`, `HEALTH_SMTP_HOST`, `HEALTH_SMTP_PORT`, `HEALTH_SMTP_USER`, `HEALTH_SMTP_PASSWORD` | للمراقبة عبر البريد | إعداد SMTP لإشعارات توقف الخدمة وتعافيها؛ لا يلزم لتشغيل التطبيق نفسه. |

لا يستخدم التطبيق حالياً `NEXT_PUBLIC_APP_URL` لإنشاء روابط مطلقة؛ لا تضفه كمتطلب إلا عند إضافة ميزة تعتمد عليه. متغيرات `NEXT_PUBLIC_*` ليست أسراراً.

## الاختبارات والبناء

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm build
pnpm start
```

نقطة الصحة: `GET /api/health`. توجد اختبارات وحدات للمسارات الحرجة، لكن لا توجد حالياً اختبارات متصفح End-to-End.

## النشر والتخزين

أوامر البناء والتشغيل وترحيلات Prisma مستقلة عن مزود استضافة محدد. **لم يُحسم اختيار المنصة بعد.**

وسائط البلاغات تُكتب محلياً في `public/uploads/incidents/`. قبل اختيار الاستضافة، تحقّق من أن نظام الملفات دائم ومشترك بين جميع نسخ التطبيق. أنظمة الملفات المؤقتة أو النشر متعدد النسخ قد يؤديان إلى فقد الملفات أو عدم ظهورها من نسخة أخرى. إذا كانت المنصة لا توفر تخزيناً دائماً مناسباً، انقل الوسائط إلى تخزين كائنات قبل الإطلاق؛ لا تفترض أن نشر Next.js خادماً بلا حالة سيحفظ هذه الملفات.

عند النشر:

1. اضبط متغيرات الإنتاج المطلوبة في إعدادات الخادم الآمنة.
2. استخدم PostgreSQL إنتاجية، وطبّق `pnpm db:migrate:deploy` مرة واحدة لكل إصدار قبل توجيه الحركة إليه.
3. أنشئ المدير الأول مرة واحدة فقط، ولا تعِد تشغيل seed روتينياً.
4. وفّر تخزيناً دائماً للوسائط ونسخاً احتياطية لقاعدة البيانات والملفات.
5. تحقق من `GET /api/health` بعد النشر.

لا تنفّذ `prisma migrate reset` على قاعدة إنتاجية. راجع [دليل النشر](./docs/deployment.md) و[دليل المراقبة](./docs/monitoring.md) لمزيد من التفاصيل.

## الملفات الحساسة

يجب أن تبقى `.env` وملفات `public/uploads/` محلية أو مخزنة في وجهة آمنة. يستثنيهما `.gitignore`؛ تحقق من ذلك قبل أي commit، ولا ترفع ملفات وسائط حقيقية إلى المستودع.
