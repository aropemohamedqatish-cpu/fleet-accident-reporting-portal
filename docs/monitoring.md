# مراقبة صحة الخدمة والتنبيه بالبريد

توفّر البوابة `GET /api/health` لفحص التطبيق وقاعدة PostgreSQL؛ تعيد `200` عند الجاهزية أو `503` عند تعذّر الاتصال بقاعدة البيانات. يسجل Next.js كذلك أخطاء الطلبات غير المعالجة في سجل الخادم.

لا يمكن للتطبيق إرسال تنبيه بعد توقفه، لذلك يستخدم ويندوز سكربتاً خارج التطبيق يفحص endpoint ويرسل بريداً عند الانتقال إلى حالة التوقف، وبريداً آخر عند استعادة الخدمة. يشغّل السكربت مرة واحدة في كل دورة، ويحفظ حالة المراقبة محلياً لمنع تكرار التنبيه أثناء استمرار العطل.

## الإعداد على Windows

شغّل المراقب على جهاز Windows مستقل ودائم التشغيل، وليس على خادم التطبيق نفسه؛ تشغيله على الخادم ذاته لن يرسل تنبيهاً إذا توقف Windows بالكامل. اضبط متغيرات البيئة التالية لحساب Windows الذي سيشغّل المهمة المجدولة:

| المتغير | الوصف |
| --- | --- |
| `APP_HEALTH_URL` | رابط الصحة الكامل، مثل `https://portal.example.com/api/health` |
| `HEALTH_ALERT_TO` | عنوان البريد المستلم |
| `HEALTH_ALERT_FROM` | عنوان البريد المرسل المسموح به من مزود SMTP |
| `HEALTH_SMTP_HOST` | خادم SMTP |
| `HEALTH_SMTP_PORT` | منفذ SMTP، افتراضياً `587` |
| `HEALTH_SMTP_USER` | اسم مستخدم SMTP |
| `HEALTH_SMTP_PASSWORD` | كلمة مرور SMTP أو كلمة مرور التطبيق |

لا تضع كلمات المرور في السكربت أو ملفات المستودع. اجعل السكربت يعمل بحساب Windows مخصص لديه أقل صلاحيات لازمة.

أنشئ مهمة في **Task Scheduler** لتشغيل كل دقيقتين:

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\path\to\project\scripts\monitor-health.ps1"
```

انسخ السكربت إلى جهاز المراقبة أو اجعل مجلد المشروع متاحاً له، واضبط **Start in** على مجلد السكربت. فعّل التشغيل حتى عند عدم تسجيل دخول المستخدم، وأنشئ مشغلاً كل دقيقتين. تحقق من إعداد SMTP بتشغيل السكربت يدوياً ثم راجع سجل المهمة والبريد. ملف `scripts/health-state.json` بيانات تشغيل محلية ويجب أن يبقى خارج التحكم بالإصدارات.

هذا المراقب يكشف توقف الموقع أو تعطل قاعدة البيانات؛ لا يكتشف كل أخطاء الأعمال داخل طلبات صحيحة HTTP. راجع سجل الخادم لمعرفة تفاصيل الأخطاء غير المعالجة.
