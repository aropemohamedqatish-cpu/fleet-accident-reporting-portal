# خطوات نشر التطبيق وقاعدة البيانات

نفّذ الخطوات على خادم التطبيق مع ضبط متغيرات البيئة المطلوبة، واستخدم `DATABASE_URL` الخاص بقاعدة الإنتاج فقط:

نقص إعدادات البيئة لا يمنع إقلاع عملية Next.js؛ يسجل الخادم أسماء الإعدادات غير الصالحة دون قيمها. ستفشل الميزات المعتمدة على الإعداد الناقص برسالة مناسبة، ويعيد `GET /api/health` الحالة `503` عند تعذّر اتصال قاعدة البيانات. أصلح إعدادات المنصة ثم أعد النشر.

> **تنبيه أمني قبل الإنتاج:** مرفقات الحوادث تُكتب حالياً تحت `public/uploads/incidents/` وتُعرض بروابط ثابتة؛ أي شخص يحصل على رابط الملف يستطيع طلبه دون جلسة إدارية. لا تستخدم هذا المسار مع مرفقات حقيقية أو بيانات إنتاجية قبل نقل الملفات إلى تخزين خاص وإضافة نقطة تنزيل تتحقق من صلاحية الجلسة. عشوائية أسماء الملفات ليست بديلاً عن التحكم بالوصول.
>
> كما يجب أن يكون تخزين الملفات دائماً ومتاحاً لكل نسخ التطبيق. أنظمة الملفات المؤقتة أو متعددة النسخ قد تفقد المرفقات أو تجعلها غير متاحة بعد النشر.

1. ثبّت الاعتماديات وابنِ التطبيق: `pnpm install --frozen-lockfile` ثم `pnpm build`.
2. طبّق ترحيلات قاعدة البيانات قبل تشغيل التطبيق: `pnpm db:migrate:deploy`.
3. في التثبيت الأول، أنشئ حساب المدير باستخدام `ADMIN_EMAIL` و`ADMIN_PASSWORD` و`ADMIN_NAME` ثم نفّذ `pnpm exec prisma db seed`. كلمة المرور المزروعة هي كلمة مرور الدخول الأول؛ أنشئها عشوائياً وبطول 12 محرفاً على الأقل، وسيُطلب تغييرها عند تسجيل الدخول. إذا كان البريد موجوداً، لا يغيّر seed كلمة المرور أو الاسم أو الدور أو حالة الحساب أو الجلسات.
4. شغّل التطبيق: `pnpm start`.
5. تحقّق من الجاهزية عبر `GET /api/health`؛ يجب أن تكون الاستجابة `200` وبالحالة `ok`.

لا تنفذ `prisma migrate reset` على الإنتاج. يمكن إعادة تشغيل seed دون إعادة ضبط حساب المدير؛ ستُضاف فقط المركبات الناقصة، ويُنشأ حساب المدير المحدد إذا لم يكن موجوداً. في النشر متعدد النسخ، طبّق الترحيلات مرة واحدة في مرحلة الإصدار قبل تحويل الحركة إلى النسخ الجديدة.

إذا لم يعمل تسجيل الدخول، افحص سجل التطبيق بحثاً عن تصنيف `schema` أو `database_unavailable`، وتحقق من نتيجة `pnpm exec prisma migrate status` ووجود حساب المدير النشط. لا تشارك `DATABASE_URL` أو `JWT_SECRET` أو كلمات المرور في السجلات أو طلبات الدعم.

يتطلب تحديد معدل واجهتي التحقق من المركبة وإرسال البلاغ تطبيق ترحيل `ApiRateLimitBucket`. الحد الحالي خمس طلبات لكل عنوان IP في الدقيقة لكل واجهة، وتستجيب الواجهة بـ `429` و`Retry-After` عند تجاوزه.
